Status: implemented

[server/specs/2026-11-28-skills.md](../../server/specs/2026-11-28-skills.md). This spec covers only the client.

## Size & risk
Medium+ (rules in [../CLAUDE.md](../CLAUDE.md)).
- **Size:** new routes/screens, many components, new hooks.
- **Risk:** shared Zod contract from `@devdigest/shared`; data hooks and TanStack Query keys; routing/layout (app-shell nav); i18n message structure.
- **Explicit exception:** edits the vendored `src/vendor/ui/nav.ts`, which `client/CLAUDE.md` marks "do not touch". Approved by the user for this feature; the change is limited to nav data (see Design). Record it in `client/INSIGHTS.md` when done.

## Context & problem
There is no UI to manage skills. The design (6 screenshots) shows a Skills Lab: a skills list with cards and a tabbed detail pane (Config, Preview, Evals, Stats, Versions), an import drawer with community search, and a Skills tab in the agent editor with attach / enable / reorder.

Already in place: `activeKeyFor` maps `/skills`; `nav.skills` in `shell.json`; `agents.json` has `editor.tabs.skills` and `skills.*` (count, filter, order hint); `AgentCard` accepts `skillCount`; vendored `Markdown` (inert images, safe links), `Drawer`, `Modal`, `Dropdown`, `Tabs`, `Toggle`, `Checkbox`, `Donut`, `MetricCard`. `messages/en/skills.json` exists but describes an older concept (URL/paste import) and is rewritten.

## Goals & non-goals
Goals
- `/skills` and `/skills/:id` with list column + tabs Config / Preview / Stats / Versions, matching the design.
- Create, edit, delete; enabled toggle on the card.
- Import from file (md/zip) with a preview-then-confirm flow; community search drawer.
- Agent editor **Skills** tab: attach, enable/disable, reorder.
- Sidebar entry and `g s` shortcut.

Non-goals
- Evals tab and "Run on evals" button (hidden/not rendered).
- Import from URL.
- New client dependencies (native HTML5 drag and drop; own diff helper).
- Editing anything else in `src/vendor/ui`.

## Design

### Navigation (`src/vendor/ui/nav.ts`, narrow exception)
- Add group `SKILLS LAB` with `skills` (icon `Sparkles`, href `/skills`, gKey `s`) and move `agents` into it, matching the design. `WORKSPACE` keeps `pulls`.

- Sidebar, command palette and global shortcuts read `NAV`, so nothing else changes. Verify the existing `g a` path still works.

### Routes
- `src/app/skills/page.tsx` → `/skills`: list column + empty detail ("Select a skill").
- `src/app/skills/[id]/page.tsx` → `/skills/:id?tab=config|preview|stats|versions` (tab in the URL, same pattern as agents; invalid tab falls back to `config`).
- Layout mirrors `agents/[id]/page.tsx`: flex row, 280px+ left column, detail right. Breadcrumb `Skills Lab › Skills`.
- Strings via `next-intl`, not hard-coded.

### Components (each `PascalCase/` with `index.ts`, `styles.ts`, colocated test)
Under `src/app/skills/_components/`
- **SkillCard**: name (mono), type badge, source (Manual / Extracted / Community / Imported), description (clamped), footer `N agents · X% pull · Y% accept` (rates hidden when `null`). `Toggle` saves immediately inside a `stopPropagation` wrapper (pattern from `AgentCard`). Dimmed when disabled. Inline delete with `window.confirm`: "Used by N agents, they will be unlinked".
- **SkillsListColumn**: heading, search (client-side filter helper), **Add Skill** `Dropdown` with `Create new`, `Import from file…`, `Search community…`. Empty / loading / error states with `EmptyState`, `Skeleton`, `ErrorState`.
- **SkillDetail**: header (name, type badge, `v{n}`), `Tabs` (no Evals), no "Run on evals".
- **ConfigTab** (controlled `useState`, no form lib, reset on `skill.id` change like the agent `ConfigTab`)
  - Name\* (kebab-case validation), Description, Type (`SelectInput`), Enabled toggle, Skill body\*.
  - Under **Description**, hint text: *"Write it as a directive: when the agent should apply this skill and what it must check. This is the skill's interface."* (the description is the interface; required by the product brief).
  - Body: `Textarea mono`, file chip `<name>.md`, `unsaved` badge when dirty, token estimate (≈ chars / 4), line numbers not required.
  - Optional "Change note" → `version_message`.
  - Save → `useUpdateSkill`; toast "Saved (v{n})". Dirty-state warning on tab/route change is out of scope (agents don't have it either).
- **PreviewTab**: `Markdown` from `@devdigest/ui` (images inert, links safe), caption "Rendered as the reviewing agent receives it". For `imported_file` / `community` sources a trust banner: *"Someone else's instructions. This text goes into your agent's prompt. Read all of it before enabling."*
- **StatsTab**: four `MetricCard` (Used by, Pull frequency, Accept rate, Findings 30d); "Agents using this skill" list (each → `/agents/:id?tab=skills`); `Donut` of findings by category with **counts** in the legend (the mock shows `$` values, which is a design bug); tooltip: "Counts runs where this skill was present; it does not prove the skill caused them."
- **VersionsTab**: list newest first, `Current` marker, **Diff** (modal; line diff via an LCS helper in `helpers.ts`), **Restore** (confirm → new version; list refetches).
- **CreateSkillModal**: same fields as Config; creates `source=manual`.
- **ImportSkillDrawer** (`Drawer`, three steps)
  1. *Choose*: `<input type="file" accept=".md,.zip,.skill">`; read with `arrayBuffer` → base64; client pre-check ≤ 1 MB. No drag-drop required.
  2. *Preview*: `POST /skills/import/preview`. Shows the editable draft (name, description, type, body), `Used` file and `Skipped` files (scripts and others listed as not processed), warnings with severity styling, and the trust block *"Imported skills are someone else's instructions inside your agent's prompt. Read the whole body. It will be saved disabled."*. Nothing is saved yet.
  3. *Confirm*: **Import** button is the only thing that calls `POST /skills/import`; on success toast, list refetch, select the new skill.
- **CommunitySkillsDrawer**: search input, filter chips (All languages, TypeScript, tags security / performance), cards (name, stars, description, repo, lang) with **Import** → fetches detail → same Preview/Confirm step as above.

Under `src/app/agents/[id]/_components/AgentEditor/SkillsTab/`
- `VALID_TABS` += `skills`; `TABS` += `{key:"skills", labelKey:"editor.tabs.skills", icon:"Sparkles"}`; `AgentEditor` renders by `tab` (it currently always renders `ConfigTab`).
- Lists **all** workspace skills: linked first in link order, then unlinked. Each row: grip handle, `Checkbox`, name, type badge. Header: "{linked} of {total} enabled" (key exists), filter input, order hint (key exists).
- Checking an unlinked skill links it (appended, enabled). Unchecking sets `enabled=false` and keeps its position. Rows for globally disabled skills are dimmed with "disabled globally, not injected".
- Reorder: native HTML5 drag and drop on the handle **plus** ↑/↓ buttons (keyboard / a11y; the e2e runner has no drag support).
- Autosave: every change sends the **full ordered set** `PUT /agents/:id/skills`; optimistic update, rollback + error toast on failure.

### Hooks (`src/lib/hooks/skills.ts`, re-exported from `hooks/index.ts`; only via `src/lib/api.ts`)
| Hook | Key | Invalidates / updates |
|---|---|---|
| `useSkills` | `["skills"]` | |
| `useSkill(id)` | `["skill", id]` | |
| `useCreateSkill` / `useImportSkill` | | `["skills"]` |
| `useUpdateSkill` | | `["skills"]`, `setQueryData(["skill", id])`, `["skill-versions", id]` |
| `useDeleteSkill` | | `["skills"]`, remove `["skill", id]`, `["agents"]`, `["agent-skills"]` |
| `useSkillVersions(id)` / `useRestoreSkillVersion` | `["skill-versions", id]` | `["skill", id]`, `["skills"]` |
| `useSkillStats(id)` | `["skill-stats", id]` | |
| `useImportPreview` | mutation | none |
| `useCommunitySkills(q, lang, tag)` / `useCommunitySkill(slug)` | `["community-skills", …]` | |
| `useAgentSkills(agentId)` / `useSetAgentSkills` | `["agent-skills", agentId]` | `["agents"]` (card `skill_count`), `["skills"]` (usage counts) |

Toggling a skill's `enabled` invalidates `["skills"]` and `["skill-stats", id]`. Per `INSIGHTS.md`, every mutation invalidates all lists whose numbers it changes.

## Risks & rollback
- **Editing vendored `nav.ts`** could diverge from upstream vendor updates. Mitigation: nav data only, documented here and in `INSIGHTS.md`.
- **Autosave ordering races** on fast reorders: serialise mutations per agent and send the full set each time; roll back to the last server state on error.
- **HTML5 DnD** is inconsistent across browsers/touch: ↑/↓ buttons are the guaranteed path.
- **Large file read in the browser**: capped at 1 MB before upload.
- **Rendering untrusted markdown**: only the vendored `Markdown` is used (no raw HTML, inert images).
- Rollback: revert the client changes; the nav edit is a few lines. The server remains backward compatible.
