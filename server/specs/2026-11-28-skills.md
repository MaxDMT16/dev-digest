# Skills: storage, CRUD, import, agent binding, prompt injection

Status: implemented

Owner spec for the Skills feature. UI and e2e specs link here:

## Size & risk
Medium+ on both axes (rules in [../CLAUDE.md](../CLAUDE.md)).
- **Size:** new module, new routes, new dependencies (`fflate`, `yaml`), well over 3 files / 150 lines.
- **Risk:** DB schema/migration; shared Zod contract and route shapes; changes review-run orchestration (`run-executor.ts`) and the content that reaches the model; handles untrusted third-party content (imported skills, zip archives).

`reviewer-core` is **not** changed. It already accepts `skills?: string[]` ([run.ts:55-56](../../reviewer-core/src/review/run.ts#L55-L56)); the server resolves and formats the blocks.

## Context & problem
Agents have only a `system_prompt`. The product needs reusable instruction blocks ("skills") that can be created, edited, deleted, imported, and attached to agents in a defined order.

State today:
- Tables `skills`, `skill_versions`, `agent_skills` exist (migration `0000`) and are empty. There is no `skills` module.
- `GET/POST /agents/:id/skills` exist ([agents/routes.ts:145-166](../src/modules/agents/routes.ts#L145-L166)) but do not check that the skill belongs to the agent's workspace, run `setSkills` without a transaction, and have no per-agent `enabled`.
- The executor never passes skills to `reviewPullRequest` ([run-executor.ts:199-221](../src/modules/reviews/run-executor.ts#L199-L221)); the trace hardcodes `skills: null` (run-executor.ts:448, [trace-builder.ts:61](../src/platform/trace-builder.ts#L61)).
- `assemblePrompt` renders skills un-fenced under `## Skills / rules` and states "community skills should be sanitized upstream" ([prompt.ts:97-118](../../reviewer-core/src/prompt.ts#L97-L118)).

**Trust model.** A skill is instructions placed in the agent's prompt. An imported skill is someone else's instructions in your agent's prompt: it can steer severity, suppress findings, or try to exfiltrate. The DB is the source of truth; nothing from an import is stored until the user confirms; imported content is saved **disabled**; executable parts of an archive are never read.

## Goals & non-goals
Goals
- CRUD over skills; the database is the source of truth.
- Description, type, markdown body; versioned on every body/description change, with restore.
- Attach skills to an agent: per-agent enable/disable and order; order defines block order in the prompt.
- Import `.md` / `.zip` / `.skill` → extract core → preview → save only after confirmation.
- Curated community catalog (search + import through the same preview/confirm path).
- Per-skill stats (usage in runs, findings, accept rate).
- Inject enabled skills, in order, into every review run; record exactly which skills/versions each run used.

Non-goals
- Evals and "Run on evals" (design shows them; deferred).
- Import from URL; live GitHub search; fetching anything over the network at import time.
- Editing `reviewer-core`'s prompt layout.
- Bumping the agent version when its skill links change.
- Sandboxing/executing skill scripts. Never.

## Design

### Data (one migration via `pnpm db:generate`)
| Table | Change |
|---|---|
| `agent_skills` | add `enabled boolean not null default true` |
| `skill_versions` | add `description text not null default ''`, `message text null` (snapshot covers both prompt-relevant fields) |
| `skills` | add `updated_at` (timestamptz, now); unique index `(workspace_id, name)` |
| `run_skills` (new) | `run_id` → `agent_runs` cascade; `skill_id` → `skills` set null; `skill_name text`, `skill_version int`, `position int`; PK `(run_id, position)` |

Other
- `SkillSource` gains `'imported_file'` (text enum → Zod/TS only).
- `SkillRow` type in `src/db/rows.ts`.
- Backfill: existing `skills` rows (none in practice) get a `skill_versions` v1 snapshot in the same migration only if any exist; otherwise nothing to do.
- Migrations are generated, never hand-edited.

### Contracts (`@devdigest/shared`; edit **both** `server/src/vendor/shared` and `client/src/vendor/shared`)
- `SkillName`: `^[a-z0-9][a-z0-9-]{1,63}$`.
- `CreateSkillBody {name, description, type, body, enabled?}`; `source` is always `manual` here.
- `UpdateSkillBody` partial + `version_message?`.
- `SkillListItem = Skill + usage {agent_count, pull_rate, accept_rate}` (rates nullable).
- `SkillVersion {version, body, description, message, created_at}`.
- `SkillStats {agent_count, pull_rate, accept_rate, findings_30d, agents[{id,name}], by_category[{category,count}]}`.
- `SkillImportRequest {filename, content_base64}`.
- `SkillImportPreview {draft{name,description,type,body}, files{used, ignored[{path,reason}]}, warnings[{code,message}]}`.
- `SkillImportConfirm {draft, source: 'imported_file'|'community', origin?}`.
- `CommunitySkill` + `slug`, `tags[]`; `CommunitySkillDetail` + `body`.
- `AgentSkillLink` + `enabled`.
- `SetAgentSkillsBody {items: [{skill_id, enabled}]}`: full ordered set; array index is the order.
- `Agent` (list DTO) + optional `skill_count` (enabled links), for agent cards.

### Routes (new module `src/modules/skills/`: `routes.ts` → `service.ts` → `repository.ts`, plus `helpers.ts`, `constants.ts`, `import-parser.ts`, `community-catalog.ts`, `index.ts`)
Register with one line in [modules/index.ts](../src/modules/index.ts). Add a `skillsRepo` getter to [container.ts](../src/platform/container.ts) for the executor. All handlers scope by `workspaceId` via `getContext`; not-found → `NotFoundError`.

| Method | Path | Behaviour |
|---|---|---|
| GET | `/skills` | `SkillListItem[]` with usage aggregates |
| GET | `/skills/:id` | `Skill` |
| POST | `/skills` | create, write v1 snapshot; 409 on duplicate name |
| PUT | `/skills/:id` | body/description change → `version+1` + snapshot (`version_message`); name/type/enabled change → no new version |
| DELETE | `/skills/:id` | cascades links; returns `{ok, unlinked_agents}` |
| GET | `/skills/:id/versions` | history, newest first |
| GET | `/skills/:id/versions/:version` | one version (for diff) |
| POST | `/skills/:id/versions/:version/restore` | new version copying that body+description; history is append-only |
| GET | `/skills/:id/stats` | `SkillStats`, 30-day window |
| POST | `/skills/import/preview` | parse only, **persists nothing** |
| POST | `/skills/import` | persist after confirmation; always `enabled=false` |
| GET | `/skills/community` | `?q&lang&tag`, searches the static catalog |
| GET | `/skills/community/:slug` | detail incl. body, for preview before import |
| PUT | `/agents/:id/skills` | (agents module) replace the full set in one transaction |

Route-order note: register `/skills/import*` and `/skills/community*` so they are not shadowed by `/skills/:id`.

Agents module fixes: every `skill_id` in `PUT`, and in the existing `POST`, must belong to the agent's workspace (else 404); `setSkills` runs in a transaction; `GET` returns `enabled`.

### Import (`import-parser.ts`: pure function, no I/O, no network)
Input: `.md`, or `.zip`/`.skill`. Transport is JSON (`content_base64`); the two import routes set `bodyLimit` to 2 MB (global default is 1 MB, [app.ts:50](../src/app.ts#L50)). No `@fastify/multipart`.

Limits (violations → 422 with a specific code)
- compressed ≤ 1 MB; ≤ 200 entries; total declared uncompressed ≤ 5 MB, **checked from zip headers before any decompression** (zip-bomb guard); core file ≤ 100 KB.
- Entry paths containing `..`, absolute paths, or backslash traversal are listed as ignored, never read.

Core selection
1. `SKILL.md` at archive root or inside the single top-level folder.
2. Else, if the archive holds exactly one `.md`, that file.
3. Else 422 `no_core_file`.

Everything except the core file is **not decompressed and not processed**. `scripts/`, `*.sh|py|js|ts|mjs|exe|bat|…`, binaries and other `.md` files are only listed in `files.ignored` with reason `skipped`. Nothing is written to disk.

Frontmatter (`yaml`, safe schema, no custom tags): `name`, `description`, `type` (valid enum else `custom`). Missing `name` → filename or first `#` heading, slugified. Missing `description` → empty; the UI makes the user write one (the description is the skill's interface, directive wording).

Warnings returned in the preview (all shown before the user confirms)
- HTML comments (hidden in rendered Preview, visible to the model);
- invisible / bidi Unicode characters;
- long base64-like blobs;
- external URLs;
- body > ~8k tokens.

Normalisation on every save path (manual, import, community, restore): strip invisible and bidi control characters.

Confirm: `POST /skills/import` takes the (possibly user-edited) draft, validates with `CreateSkillBody`, stores `source = imported_file | community`, `enabled=false`, v1 snapshot. Name collision → 409 (UI offers rename).

### Community catalog
Static curated list in `community-catalog.ts` (name, repo, stars, lang, tags, description, body). Search = case-insensitive match on name/description/tags + `lang`/`tag` filters. Imported through the same preview → confirm path, `source='community'`, saved disabled. No outbound requests.

### Prompt injection (server side)
`runOneAgent` ([run-executor.ts](../src/modules/reviews/run-executor.ts)):
1. `skillsRepo.resolvedForAgent(agentId)` → skills with `agent_skills.enabled AND skills.enabled`, ordered by `agent_skills.order`.
2. `formatSkillBlock(skill)` per skill:
   ```
   <skill name="pr-quality-rubric" type="rubric" version="5">
   Description: <description>

   <body>
   </skill>
   ```
   Any `</skill` in name/description/body is escaped (same approach as `wrapUntrusted`'s `</untrusted>` escape).
3. Pass `...(skills.length ? { skills } : {})` next to `callers`/`repoMap`. The strings land under `## Skills / rules` in block order.
4. Insert `run_skills` rows (`name`, `version`, `position`) for the run.
5. Replace the hardcoded `skills: null` in the failure-path trace and `trace-builder.ts` with the joined blocks.

Residual risk, stated plainly: skill blocks are **not** fenced as `<untrusted>`. They are the owner's instructions and must be able to steer the review. Protection for imported content is therefore (a) preview + warnings, (b) saved disabled, (c) user must read and enable, (d) invisible-char stripping. Skills must not redefine severity scale or output format; the engine enforces the schema regardless ([docs/agent-prompts/README.md](../../docs/agent-prompts/README.md)).

### Stats (SQL aggregates, 30-day window)
Metrics are **correlational**: they describe runs in which the skill was present, not an effect of the skill.
| Metric | Definition |
|---|---|
| `agent_count` | enabled links |
| `pull_rate` | share of reviewed PRs (30d) with ≥1 run that has this skill in `run_skills` |
| `findings_30d`, `by_category` | `findings` joined via `reviews.run_id` ∈ `run_skills` of this skill |
| `accept_rate` | accepted / (accepted + dismissed) over those findings; `null` when no decisions |

### Seed ([seed.ts](../src/db/seed.ts) + new `seed-skills.ts`)
Six demo skills from the design (`pr-quality-rubric`, `no-then-chains`, `secret-leakage-gate`, `lethal-trifecta`, `phantom-api-gate` disabled, `test-coverage-nudge`); links to Security Reviewer in the design order; idempotent by name like agents. Seeded `agent_runs` may also get `run_skills` rows so Stats are non-empty in the demo (see open questions).

## Risks & rollback
- **Prompt injection via imported/community skill** (main risk): mitigations above; residual risk accepted and documented.
- **Zip bomb / path traversal / oversize**: header-based size checks before decompression, entry and size caps, only the core entry is ever read, nothing touches disk.
- **Unique `(workspace_id, name)` index** could fail on existing data: tables are empty today; migration checks nothing else.
- **Cross-workspace linking** is closed by the workspace check (previously open).
- **Stats mislead**: correlation caveat in contract docs and UI tooltip.
- **Seed change breaks e2e 02/04**: those assert PR/run values only; verified in the e2e spec.
- **Rollback:** feature is additive. Revert code; leave the migration (additive columns/table) or write a follow-up down-migration via drizzle-kit. Behaviour with zero linked skills is identical to today.
